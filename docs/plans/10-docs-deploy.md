# Plan 10 — Documentation & Deployment

## Documentation

### `README.md`
Covers the purpose of the project (an accessibility testing fixture disguised as a university), a screenshot, the tech stack, and these steps: install (`npm ci`), run (`npm run dev`), build (`npm run build` writes `build/client`), preview (`npm run preview`), and test. It also covers deploying to each host, the route count, the image credits (Nano Banana in Google Flow), and a clear statement that the institution is fictional.

### `ACCESSIBILITY_TESTING.md`
- The three categories and how Errors, Alerts, and Manual issues differ, with examples.
- How the toggles work: the store, body classes, `useScenario`, and the no-persistence rule.
- The registry schema and rule taxonomy.
- **How to add a scenario,** as a four-step recipe with a worked example.
- Testing walkthroughs:
  - **WAVE:** scan with all toggles OFF, turn on Fix Errors, then rescan. The document explains that toggle state lives in the page, so extension scans use the current DOM.
  - **axe DevTools and the Playwright script:** run `npm run scan -- /academics/catalog` to print a before and after table.
  - **Keyboard:** a checklist of pages and what to try on each.
  - **Screen readers:** basic NVDA, VoiceOver, and Narrator steps against the portal, forms, and live regions.
  - **Zoom and reflow:** 200%, 400%, and the text-spacing bookmarklet.
- Known tool differences, where WAVE and axe disagree.

### `SITE_MAP.md`
Generated by `scripts/gen-sitemap-md.ts` from `inventory.ts`. It lists routes by section with each route's tier and scenario counts, so it never drifts from the code.

## Deployment

| Host | Setup |
|---|---|
| Cloudflare Pages | Build `npm run build`, output `build/client` |
| Netlify | Same, plus `_redirects` with `/* /404.html 404` |
| Vercel (static) | Framework preset "Other", output `build/client` |
| GitHub Pages | `BASE_PATH=/a11y_university/ npm run build`. A workflow uploads `build/client`, and `404.html` is copied. |

- Every route is prerendered, so no SPA rewrite is needed for known paths. Unknown paths show the 404.
- Add a `robots.txt` with `noindex` and a `<meta name="robots" content="noindex">` in the shell. This keeps search engines from indexing the site and mistaking it for a real university.
- Put a small, accessible "Fictional university — accessibility test site" notice in the footer. This matters legally and ethically. It's also accessible infrastructure, not a scenario.

## Final verification (PRD completion gate)

1. Generate the route inventory and check the count against the target.
2. Generate the scenario inventory and coverage matrix. All 17 areas must be covered.
3. Run the full CI suite and make sure it's green.
4. Manually test with WAVE on 10 pages across tiers, before and after each toggle, and record the results in `docs/verification.md`.
5. Do a hard reload on stateful pages and confirm the reset.
6. Deploy a preview to one static host and smoke-test direct links.
